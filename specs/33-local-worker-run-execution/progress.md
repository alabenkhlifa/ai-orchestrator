Fixed in `GatewayConnection` (not in the consumed-unchanged adapter boundary): undelivered events from a partial failure are now kept in `socket.assigns.pending` (along with the batch's own terminal marker, if any) and retried on the next tick *before* polling the adapter for anything new — `AgentObserver.poll/3` is never called again while a pending, not-yet-delivered batch still exists. This closes the data-loss path without changing `AgentObserver`'s or the adapters' own contracts. Not covered by a dedicated regression test: because one poll tick's whole event batch is delivered synchronously within a single `handle_info/2` execution, a genuine transport failure cannot be made to land *between* two pushes of the same tick from an external test process (the connection process cannot process a disconnect notification while already executing that handler) — triggering the exact failure window would require mocking the push/ack call itself rather than exercising the real channel, which every other test in this suite deliberately avoids.
