- Discovery result (main-thread review, before accepting the sub-agent's result): `AgentAdapter.observe/2` — via each adapter's `Session.drain/1` (Tasks 6/7, consumed unchanged) — is a **destructive read**: every call clears the adapter's internal event buffer unconditionally, whether or not the caller goes on to actually deliver what it returned. The sub-agent's original delivery loop discarded the undelivered remainder of a batch on a mid-tick push/ack failure and simply retried the same tick later — but retrying means calling `AgentAdapter.observe/2` again, which cannot re-return content already drained and lost; a transient ack failure partway through a batch would permanently lose whatever wasn't yet acknowledged, and if the lost item was the attempt's own terminal event, the attempt would never transition and would stay `"accepted"` forever with its lock never released. Confirmed by reading `Session.drain/1`'s `handle_call(:drain, ...)` clause directly (unconditional `%{state | events: []}}` on every call) before touching anything. Fixed in `GatewayConnection` (not in the consumed-unchanged adapter boundary): undelivered events from a partial failure are now kept in `socket.assigns.pending` (along with the batch's own terminal marker, if any) and retried on the next tick *before* polling the adapter for anything new — `AgentObserver.poll/3` is never called again while a pending, not-yet-delivered batch still exists.
