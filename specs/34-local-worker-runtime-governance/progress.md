### 2026-08-08 - Design corrected before implementation: no `ObservationAdapter.LocalWorker`, no ingestion

Everything else is refused. - Fix verified against the actual code, not assumed: `RuntimeProjections.owner_projection/3` and `participant_projection/4` (`lib/sdd_orchestrator/ai_runtime/runtime_projections.ex`) already handle an empty observation list as an ordinary case — `list_observations/3` returns `{:ok, []}`, `latest_observation/2` returns nothing, availability degrades to `:unknown` — so the pinned connection's model, effort, and quota still project correctly with zero ingested observations. The mechanism this slice now uses: a live, read-only elapsed-time-and-status snapshot computed directly from the referenced `AgentRun`/`RunAttempt`'s own already-existing state (no new module under `ai_runtime/`, no schema, no persisted observation), combined with the unchanged reused projection for connection/model/effort/quota. `capability:ai-runtime-observation` is still required and still consumed — through its projection functions only, never through `ingest/3`.
